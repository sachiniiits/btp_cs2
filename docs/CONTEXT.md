## 1. Project overview

This pipeline parses raw CS2 `.dem` demo files from professional matches and
produces a behavioural role label for every player-round observation without
any labelled training data. It is the backbone of a BTP (Bachelor's Thesis
Project) on unsupervised role discovery in esports.

**Unit of analysis:** one row = one player playing one round in one match.

**Approach:**

```
.dem files  →  Feature engineering  →  Ensemble clustering  →  Role labels
              (14 per-round metrics)    (KMeans + GMM + HDBSCAN)
```

The pipeline is self-contained in a single Google Colab cell
(`cs2_pipeline_v3.py`) and writes all outputs to Google Drive.

## 6. Pipeline architecture

The pipeline is split into two logical stages:

### G1 — Feature extraction & preprocessing

```
parse_dem_file()
    │
    ├── player_death events  →  kills_df
    ├── player_hurt events   →  damage_df
    ├── position ticks       →  pos_df        (every 64th tick)
    ├── grenade events       →  grenades_df
    └── round_end events     →  round_ends_df
            │
            ▼
    reconstruct_rounds()     →  round_map  (tick boundaries per round)
    assign_round_num()       →  round_num column on each DataFrame
            │
            ▼
    For each (player, round, side) combo:
        ├── kill_count
        ├── damage_dealt
        ├── utility_used
        ├── distance_traveled        distance_traveled()
        ├── mean_isolation           mean_isolation() via cKDTree
        ├── zone_primary             compute_zone_primary() — percentile-based
        ├── headshot_pct
        ├── trade_kills              compute_trade_kills()
        ├── flash_assists            compute_flash_assists() — assister_name
        ├── first_engagement_rel
        ├── death_tick_rel
        ├── multi_kill_round
        ├── survived
        └── opening_duel_won
            │
            ▼
    preprocess()
        ├── clip all features to caps
        ├── log1p transform on [damage, distance, isolation]
        ├── StandardScaler on log + count features
        └── passthrough scaled alias for [fe_rel, dt_rel, zone, hs_pct, duel]
            │
            ▼
    g1_features.parquet  (raw)
    g1_clean.parquet     (scaled)
```

### G2 — Clustering & role assignment

```
g1_clean.parquet  →  X_scaled  (2028 × 14 matrix)
        │
        ├── Correlation matrix              → g2_correlation_matrix.png
        │
        ├── K selection (k = 3..7)
        │   ├── Silhouette score (KMeans)
        │   └── BIC (GMM)                   → g2_k_selection.png
        │   └── Optimal K = compromise average
        │
        ├── Ensemble clustering
        │   ├── KMeans   (n_init=10)
        │   ├── GMM      (n_init=5, full covariance)
        │   └── HDBSCAN  (min_cluster_size=20, min_samples=5)
        │       └── align labels via Hungarian algorithm
        │       └── majority vote → consensus cluster_id
        │
        ├── Dimensionality reduction
        │   ├── PCA (2 components)          → g2_pca_tsne.png
        │   └── t-SNE (perplexity=30)
        │
        ├── Cluster profiling
        │   ├── Mean original features per cluster
        │   ├── Normalised heatmap          → g2_profile_heatmap.png
        │   └── Radar charts per cluster    → g2_radar_charts.png
        │
        ├── Role scoring
        │   └── Weighted score vectors → greedy assignment → role_label
        │                                                  → g2_roles_final.png
        │
        └── Player-level aggregation
            └── dominant role + consistency %             → g2_player_roles.png
```

## 7. Feature set (G1)

All features are computed at **player × round** granularity.

### Raw features

| Feature | Type | Range | Description |
|---|---|---|---|
| `kill_count` | int | [0, 5] | Kills in the round, capped at 5 |
| `damage_dealt` | float | [0, 500] | Total hp damage to enemies |
| `utility_used` | int | [0, 5] | Grenade/inferno events fired |
| `distance_traveled` | float | [0, 5000] | Sum of consecutive 2D position deltas |
| `mean_isolation` | float | [0, 2000] | Mean nearest-teammate distance via cKDTree |
| `zone_primary` | int | {1, 2, 3} | Map position: 1=CT-side, 2=mid, 3=T-side (percentile-based) |
| `headshot_pct` | float | [0, 1] | Fraction of kills that were headshots |
| `trade_kills` | int | [0, 5] | Kills within 320 ticks of a teammate's death |
| `flash_assists` | int | [0, 5] | Rounds where player was credited an assisted-flash kill |
| `first_engagement_rel` | float | [0, 1] | Normalised tick of first kill (1.0 = never got one) |
| `death_tick_rel` | float | [0, 1] | Normalised tick of death (1.0 = survived) |
| `multi_kill_round` | int | {0, 1} | 1 if player got ≥3 kills in the round |
| `survived` | int | {0, 1} | 1 if player did not die in the round |
| `opening_duel_won` | int | {-1, 0, 1} | +1 = won first duel, -1 = lost first duel, 0 = uninvolved |

### Scaled features used for clustering

| Raw feature | Transformation | Scaled column name |
|---|---|---|
| `damage_dealt` | log1p → StandardScaler | `damage_dealt_log_scaled` |
| `distance_traveled` | log1p → StandardScaler | `distance_traveled_log_scaled` |
| `mean_isolation` | log1p → StandardScaler | `mean_isolation_log_scaled` |
| `kill_count` | StandardScaler | `kill_count_scaled` |
| `utility_used` | StandardScaler | `utility_used_scaled` |
| `trade_kills` | StandardScaler | `trade_kills_scaled` |
| `flash_assists` | StandardScaler | `flash_assists_scaled` |
| `multi_kill_round` | StandardScaler | `multi_kill_round_scaled` |
| `survived` | StandardScaler | `survived_scaled` |
| `first_engagement_rel` | passthrough | `first_engagement_rel_scaled` |
| `death_tick_rel` | passthrough | `death_tick_rel_scaled` |
| `zone_primary` | passthrough | `zone_primary_scaled` |
| `headshot_pct` | passthrough | `headshot_pct_scaled` |
| `opening_duel_won` | passthrough | `opening_duel_won_scaled` |

**Design note on collinearity:** `distance_traveled` and `mean_isolation`
correlate at r=0.93. Both are retained because they encode related but
distinct signals — distance measures total roaming while isolation measures
positional separation from teammates at any given moment. The Lurker role
weight for `distance_traveled` is intentionally reduced to avoid
double-counting.

## 8. Clustering & role assignment (G2)

### K selection

Silhouette score (KMeans) and BIC (GMM) are computed for k ∈ {3, 4, 5, 6, 7}.

- If Silhouette and BIC agree within 1: use Silhouette result
- Otherwise: `OPTIMAL_K = round((k_sil + k_bic) / 2)`, clamped to [3, 7]

In v3 runs: Silhouette→3, BIC→7, resolved to **K=5**.

### Ensemble clustering

Three algorithms run independently, then their labels are reconciled:

1. **KMeans** — centroid-based, fast, used as the reference label set
2. **GMM** — soft probabilistic boundaries; labels aligned to KMeans via
   the Hungarian algorithm (linear sum assignment on a cost matrix)
3. **HDBSCAN** — density-based; noise points (label=-1) are reassigned to
   their KMeans cluster before alignment; `min_cluster_size=20`

Final label = majority vote across the three aligned label sets.
`gmm_max_prob` (highest GMM posterior for a row) is retained as a
per-row confidence estimate.

### Role scoring

Each cluster is scored against 6 weighted role templates using its
mean scaled feature values. Scores are real-valued; higher = better match.

```python
roles_def = {
    "Entry":   {fe_col: -2.5, dmg_col: +2.0, kill_col: +1.5,
                surv_col: -1.0, open_col: +2.0, multi_col: +1.0},
    "Support": {ut_col:  +3.0, iso_col: -2.0, trade_col: +2.0,
                flash_col: +2.0, surv_col: +0.5},
    "Lurker":  {iso_col: +2.5, fe_col:  +1.5, dist_col: +1.0,
                surv_col: +1.0, trade_col: -1.0},
    "AWPer":   {hs_col:  -2.5, dmg_col: +1.5, dist_col: -1.5,
                kill_col: +1.0, iso_col: +0.5},
    "IGL":     {ut_col:  +1.5, surv_col: +2.0, open_col: -1.5,
                flash_col: +1.0, kill_col: -1.0, multi_col: -1.0},
    "Rifler":  {dmg_col: +2.0, kill_col: +2.0, hs_col:   +1.5,
                fe_col:  -1.0, surv_col: +0.5, multi_col: +1.0},
}
```

Assignment is greedy: clusters are sorted by their best score descending,
and each cluster claims its highest-scoring unclaimed role. Clusters that
score negatively on all roles should be assigned Flex (score threshold
check — planned for v4).

### Player-level aggregation

After round-level labelling, rows are grouped by `player_name`:

- `dominant_role` — most frequent round-level role label
- `role_consistency` — fraction of rounds matching dominant role
- `final_role` — dominant role if consistency ≥ 50%, else "Flex"

## 9. Role definitions

| Role | Tactical description | Key signals |
|---|---|---|
| **Entry** | First into site; trades kills for map control | Low `first_engagement_rel`, high damage, high opening duels, dies often |
| **Support** | Enables teammates; throws utility for others | High `utility_used`, high `flash_assists`, low `mean_isolation` |
| **Lurker** | Flanks independently; delays rotations | High `mean_isolation`, late engagement, high `distance_traveled` |
| **AWPer** | Long-range precision; holds angles statically | Low `headshot_pct` (AWP always HS), low `distance_traveled`, moderate damage |
| **IGL** | In-game leader; calls rounds conservatively | High survival, high utility, negative opening duel tendency |
| **Rifler** | Efficient fragger; consistent damage output | High damage + kills + headshot_pct, survives more than Entry |

**AWPer headshot note:** The AWP always registers as a headshot in CS2
kill events regardless of where the shot lands. Low `headshot_pct` in a
cluster therefore signals AWP usage (all kills are headshots → hs_pct is
high for most players → AWPer cluster has relatively lower hs_pct among
non-AWP kill events, but the weight is set negative to capture this
inversion correctly against the rifler baseline).

## 13. Known limitations

| Limitation | Detail |
|---|---|
| Ensemble agreement low (28.7%) | K=3 (Silhouette) vs K=7 (BIC) gap means algorithms solve different problems; data has ~3 natural clusters, not 5 |
| Cluster 4 → AWPer mislabelled | Passive/dying cluster with near-zero kills; gets AWPer because all other roles taken; needs score threshold → Flex |
| Entry role never assigned | Entry and Rifler collapse onto same cluster (both high damage/kills); needs k=6 to separate |
| Budapest demos undersampled | 20 rows each instead of ~250; likely demo version difference on StarLadder server |
| Flex dominates player-level (21/31) | Only 12 matches ≈ 65 rounds/player; insufficient for stable 50% consistency |
| distance/isolation collinearity r=0.93 | Both features kept but partially redundant; consider PCA pre-processing or dropping one |
| No ground truth labels | No confusion matrix available for real demo data; validation is structural only |

## 14. Future work

- **Fix K=6 hardcoded** — bypass Silhouette/BIC compromise; use fixed K matching number of role definitions so each role gets a dedicated cluster
- **Score threshold for Flex** — if `max(role_scores[cid].values()) < 0`: assign Flex; prevents bogus role labels on passive clusters
- **Separate Entry from Rifler** — widen `surv_col` weight gap in scoring weights (Entry: -2.0, Rifler: +1.0) to split them once k=6 provides separate clusters
- **Budapest demo investigation** — inspect `parser.parse_header()` on the two low-yield demos; check demo format version vs the other 10
- **Expand demo pool** — more matches → more rounds per player → higher consistency scores at player level; target 20+ matches
- **Weapon-based AWPer verification** — cross-reference `weapon` column from kills_df to post-hoc identify confirmed AWP users and validate cluster assignment
- **Side-stratified clustering** — run G2 separately for T-side and CT-side rows; roles behave differently on each side (Support CT-side ≠ Support T-side)
- **Soft GMM labels** — use GMM posterior probabilities as feature weights in final label voting instead of hard majority vote; should improve ensemble agreement
